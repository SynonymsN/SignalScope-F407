# SignalScope-F407 Validation

## Firmware Status

Built artifact:

```text
build/Debug/SignalScope_F407.elf
```

Validated on board with STM32CubeProgrammer:

- ST-LINK detected STM32F405/F407 target.
- Target voltage: 3.20 V.
- Firmware download and verify succeeded.
- FreeRTOS acquisition data continued changing after reset.

## Screen Checklist

After reset, the LCD should show a landscape instrument-style LVGL dashboard:

- Title: `SignalScope-F407`.
- Top-right state pill: `RUN`, `STOP`, or `SINGLE`.
- Left side: main waveform chart with a moving line.
- Header source label: `EXT PA5`.
- Header status line:
  - `NO SIG WAIT`: no useful external amplitude detected.
  - `SIG WAIT`: amplitude detected, trigger/frequency not stable yet.
  - `SIG LOCK`: external signal and trigger edge detected.
  - `RAIL`: input is close to the ADC rail. This is expected for a full-swing F103 logic square wave, but unknown signals still need input protection.
- Right side: six metric cards: `Fs`, `Sig`, `Vpp`, `Avg`, `Range`, and `Duty`.
  Each card has its own border and value area.
- Bottom row in external-input mode: `IN`, `TR`, `SG`, and `RL` indicators
  for input level, trigger lock, signal present, and rail proximity.
- Bottom control strip: `K0 STOP/RUN`, `K1 AUTO`, `K2 TR-`, and `WK TR+`
  action boxes, plus a short action/diagnostic message.
- When no key action is being shown, the bottom message should look like
  `EVxxx OV0 STKx/x/x HBx/x/x`.
  - `EV` should keep increasing while ADC DMA is running.
  - `OV` should normally stay at `0`; if it rises continuously, the acquisition
    task is not consuming DMA half-buffers fast enough.
  - `STK` shows the minimum remaining stack words for acquisition/control/UI
    tasks. A very small value means that task stack should be increased.
  - `HB` shows task heartbeat age in milliseconds. Large or frozen values point
    to a blocked task.

## Key Test

- Press `KEY0`: the state should toggle between `RUN` and `STOP`.
- Press `KEY1`: trigger level is automatically moved to the midpoint of the
  current PA5 waveform. If no useful signal is present, it returns to 1650 mV.
- Press `KEY2`: trigger level decreases by 100 mV.
- Press `WK_UP`: trigger level increases by 100 mV.
- Press `KEY0 + KEY1`: frame, trigger, overrun, and edge counters are cleared.
  The DMA event/overrun diagnostics are reset as well.
- Press `KEY2 + WK_UP`: one single frame is captured.

## ST-LINK Runtime Check

The latest landscape build placed `s_scope` at:

```text
s_scope = 0x20002c58
stats   = 0x20002d58
```

Read the statistics area:

```powershell
& '<STM32CubeProgrammer>/bin/STM32_Programmer_CLI.exe' -c port=SWD mode=HOTPLUG freq=4000 -r32 0x20002D58 96
```

Expected signs:

- `sample_rate_hz` should be `0x0000BB80`, which is 48000 Hz.
- `source_freq_hz` starts from the measured ADC window. With no external signal
  it may be `0`; with the F103 1 kHz square source it should settle near 1000 Hz.
- `frame_count`, `trigger_hits`, and `last_update_ms` should increase over time.

Final measured example for the metric-card landscape build:

```text
frame_count  : 0x058B -> 0x0D2C
trigger_hits : 0x0D5D -> 0x1FC4
```

## Current Boundary

This firmware is a runnable LVGL/FreeRTOS low-voltage signal-terminal prototype.
It starts in real `PA5 / ADC1_IN5 / STM_ADC` mode. The front-panel workflow stays on
external input; any waveform used for validation must come from F103 PA1, a
function generator, or another safe 0-3.3 V source.

With external wiring, the waveform enters the MCU through PA5 / STM_ADC. The current
validated external-source setup is `F103 PA1 -> F407 PA5` plus common ground.
It can also measure a safe 0-3.3 V waveform generated by a signal generator,
PWM output, or sensor front-end.

Explorer V3 hardware note: `PA1` is connected to the Ethernet PHY reference
clock path and should not be used as the external ADC input. Use `PA5 / STM_ADC`
instead. Remove the `P11` jumper if PA5 must be fully independent from the
board touch/ADC circuit.

The real acquisition path is:

```text
TIM3 trigger -> ADC1 conversion -> DMA2 circular buffer
-> half/full DMA interrupt -> acquisition task notification
-> half-buffer processing -> triple-buffered snapshot -> LVGL UI
```

The optimized build should be judged by these runtime signs:

- `EV` increases roughly every DMA half-buffer, proving that the acquisition
  path is interrupt/event-driven.
- `OV` stays at `0` or only changes during abnormal pauses, proving that the
  acquisition task keeps up with DMA.
- Waveform metrics remain correct for the F103 source: `Sig` near 1 kHz,
  `Vpp` near 3.2 to 3.3 V, `Avg` around 1.6 V, and `Duty` around 50%.
- Pressing keys still changes run state, trigger level, clear statistics, and
  single capture behavior.

Do not describe the current build as a calibrated oscilloscope. It is currently
the board-side UI and acquisition-processing framework.
